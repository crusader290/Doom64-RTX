## What works in Doom64-RTX

These are mods for GZDoom-RT running *Doom 64: Retribution*. Doom64-RTX runs the original
N64 game code, so only the **art** in them can be used:

| Content | Used? |
|---|---|
| `sprites/*.png`, `textures/*.png`, `flats/*.png`, `graphics/*.png` whose names match Doom 64 lumps | yes, as replacements (see README "Resource packs") |
| ZSCRIPT, DECORATE, MAPINFO, GLDEFS, UDMF maps (TEXTMAP), ACS | no (GZDoom only), listed in doom64rtx.log |
| `Retribution-RT-Materials/rt/mat/*_{orm,n,e}.png` and `rt/data/*.json` (RTGL1 conventions: G = roughness, B = metallic in `_orm`; light colours) | yes, by the ray tracer (`_h` and the `_dev`/quarantine copies are ignored) |

Release builds load one `packs/doom64rtx-visuals.pk3`, generated by
`python3 tools/pack_visuals.py <output.pk3>`. It combines the lost-soul and
fireball sprites, compatible `SFLATC`/`SPACECE` ceiling-light PNG lumps, and
RT material maps/defaults. Its manifest records every entry's source.
Original archives stay here for attribution and future compatibility work.

The broken SFLATAS test, GZDoom scripts/maps, quarantine/development maps and
unused height maps are excluded. The pack does not replace every world texture:
most archived images are material maps rather than new base-colour artwork.
You can still load individual archives with `-pack <file>` for development.
